# APP 字符串接收与按键判断

蓝牙收发留在主程序。将收到的字符串传给“接收并解析 APP 数据”，库按 `#` 分出每条指令，内部执行解析。左右 pad 只更新状态，由主程序用“APP 左／右 pad 按键 上／下／左／右 被按下”判断后定义动作。

## 如何运行

完整 APP 示例使用 micro:bit V2。在 MakeCode 新建项目，添加 RobotShield 和 Bluetooth 扩展，将 [APP 示例](../examples/arm-app.ts) 复制到 main.ts。修改初始化中的四关节输出通道以匹配实际接线。

1. 使用 `armInitialize(...)` 配置输出通道。
2. 调用一次 `armAppPrepare()`，将机械臂动作接入 APP 调度；此步骤沿用原有的四关节回 90°动作。`armInitialize()` 本身不设置角度。
3. 收到字符串后调用 `armAppReceive(data)`。
4. 在重复执行中用 `armAppIsPressed(...)` 判断按键，并调用自己的动作；保留 `armAppUpdate()` 和 20 毫秒等待。
5. 蓝牙断开时调用 `armAppStop()`，清除按键、接收缓存和待执行动作。

## 接收字符串片段

传入的数据应保留 `#`，一条指令只有收到 `#` 才会执行。例如：

```typescript
Acebott.armAppReceive("11")
Acebott.armAppReceive("01#1204#1301")
Acebott.armAppReceive("150#")
```

内部依次得到 `1101#`、`1204#`、`1301150#`：左 pad 上按下、右 pad 右按下、夹爪目标 150°。既支持一条分多次传入，也支持一次传入多条；未结束的尾段保留到下次。不要先把整条指令转为数字，前导零需要保留。

MakeCode 自带“蓝牙读取直到 #”会去掉 `#`，因此示例补回结束符：

```typescript
Acebott.armAppReceive(bluetooth.uartReadUntil(serial.delimiters(Delimiters.Hash)) + "#")
```

如果你已有直接读取字符串片段的方式，原样传入即可，无需自己分割。空指令被忽略；单条超过 96 字符会丢弃到下一个 `#` 并报告错误，再继续解析后续指令。

## pad 判断

```typescript
if (Acebott.armAppIsPressed(Acebott.ArmAppSide.Left, Acebott.ArmAppButton.Up)) {
    // 在这里编写你要执行的动作。
}
```

返回布尔值，可直接放进“如果”。`ArmAppSide` 选择 `Left`／`Right`，`ArmAppButton` 选择 `Up`／`Down`／`Left`／`Right`。

同一侧保持最新的一个方向，左右两侧互不覆盖。收到 `1100#` 清除左侧，`1200#` 清除右侧；没有新指令时保持原状态。主程序调用关节、滑块、XYZ、记忆等动作不会假装按键已松开。断开时调用 `armAppStop()` 清除两侧。

原 `armAppSetJoystick(...)` 设置积木已移除。接收方向键指令和调用 `armAppUpdate()` 都不会自动驱动 pad 对应的关节。[完整示例](../examples/arm-app.ts) 在主程序的“如果”中演示了指令表的八个方向映射，动作可自行修改。示例的 pad 目标也经过现有调度，每 120 毫秒应用最新关节目标。

## 指令表

下表所有指令均以 `#` 结尾。

| 指令 | 解析结果 |
| --- | --- |
| `1100`～`1104` | 左 pad：00 松开；01 上、02 下、03 左、04 右。只更新按键状态。 |
| `1200`～`1204` | 右 pad：00 松开；01 上、02 下、03 左、04 右。只更新按键状态。 |
| `1301`、`1302`、`1303`、`1304` + 角度 | 依次设置夹爪、肘部、肩部、底盘目标。角度文本为 0～180 的整数。 |
| `1401` + XYZ 文本 | 坐标移动。例如 `14017 13 2#`、`14017,13,2#` 或固定三位数字 `1401007013002#`，均表示 X=7、Y=13、Z=2。 |
| `1501` | 四关节回 90°，保留当前 XYZ 原点。 |
| `1601`、`1602`、`1603` | 开始记录、保存姿态、结束记录。 |
| `1604`、`1605`、`1606`、`1607` | 单次回放、清除当前组、循环回放、停止。 |
| `1701`、`1702`、`1703` | 选择第 1、2、3 组记忆。 |

滑块和 XYZ 指令只排入待执行目标，后续由 `armAppUpdate()` 推进。高频滑块只保留每个关节的最新目标，每 120 毫秒应用一次。保留原有限位与校准：肘部最大 120°，夹爪最小 90°；XYZ 仍由机械臂的范围及关节联动限位检查决定能否执行。

## 记忆与结果

三组记忆各最多 20 个姿态。选择组后，先“开始记录”，再“保存”，最后“结束记录”。切换组会停止当前记录和回放，保留其他组的数据。回放采用 30 步插值，每步约 20 毫秒，并保留姿态间停顿；主程序实际发出手动动作时可中断回放。

`onArmAppResult` 提供动作结果和解析错误，由主程序决定显示、打印或发送。库本身不调用蓝牙。沿用原 APP 的选组确认文字 `17011`、`17021`、`17031`；示例发送时统一加 `#`。没有接入结果回调也能解析指令。

XYZ 使用机械臂库现有的坐标换算、校准和限位。新关节目标、回位、回放或停止可以取消剩余 XYZ 步骤；取消的旧动作不会返回过期的 XYZ OK。

普通搬运程序不调用 `armAppPrepare()` 时，原有动作仍直接执行。`armHomePose()` 回 90°并保留原点；`armReset()` 回 90°后将该姿态设为 XYZ 原点。APP 的 `1501#` 沿用前者。
